# Optimizer, greyscale and JPEG 2000 problem samples

Small hand-built PDFs (under 11 KB each, 84 KB in total), one per structural oddity
that broke PDF optimisation, greyscale conversion or JPEG 2000 decoding in Office
Convert / Stirling-PDF's compress tool. Each is the smallest file that still
triggers the problem.

## Licence and provenance

Every file is generated by [`../scripts/make_optimizer_cases.py`](../scripts/make_optimizer_cases.py)
using only the Python standard library, so it is covered by this repository's MIT
licence. Nothing is copied from third-party documents:

- the only font is the standard Helvetica, referenced by name and not embedded
- images are gradients computed in the script
- the two JPEG 2000 codestreams are 8x4 test patterns that OpenJPEG encoded from
  generated pixels, stored as base64
- Brotli streams use stored (uncompressed) meta-blocks written by the script

Regenerate with:

```bash
python3 common/scripts/make_optimizer_cases.py common/optimizer
```

The output is byte-identical every run except `encryption/owner-password-aes256.pdf`,
because AES picks a random IV. That case needs `qpdf` and is skipped without it.

## The samples

| File | What is unusual | What went wrong / what to check |
| --- | --- | --- |
| `filters/brotli-content-stream.pdf` | Page content uses `/BrotliDecode` (PDF 2.0 extension proposal) | Greyscale decoded it, then failed writing it back: PDFBox has no Brotli encoder. qpdf, poppler and most viewers can't read it at all. |
| `filters/brotli-chained-filters-with-predictor.pdf` | `[/ASCIIHexDecode /BrotliDecode]` chains on content and on an image, with a PNG predictor on the Brotli stage of the image | Greyscale kept the image in colour because PDFBox can't decode the Brotli stage |
| `filters/flate-predictor-content-stream.pdf` | A content stream (not an image) stored with a Flate PNG predictor | Regression check (no failure seen): a tool that rewrites the content must not keep the old predictor parameters on new data |
| `colour/pattern-space-shared-across-pages.pdf` | One indirect `[/Pattern /DeviceRGB]` space and one resource dictionary shared by two pages | Greyscale converted the first page's pattern colour, then saw the space already rewritten and left the second page in colour |
| `colour/pattern-space-reused-in-one-stream.pdf` | The same pattern colour space set twice in one content stream | Same bug, inside a single stream |
| `colour/mesh-shading-with-predictor.pdf` | Type 4 (free-form triangle) mesh shading whose stream has a Flate predictor | Regression check (no failure seen): greyscale rewrites the mesh colours in place, so it must decode with the predictor and write back without it |
| `images/inline-image-samples-spell-ei.pdf` | An inline image whose raw samples contain the bytes ` EI ` | A rewritten inline image in binary can end early in some readers; it has to be hex-encoded |
| `images/indexed-image-over-gray.pdf` | `[/Indexed /DeviceGray ...]` image, already grey | Greyscale re-encoded already-grey images and made them larger (one real file went from 193 KB to 266 KB) |
| `images/separation-over-gray-image.pdf` | Separation image with a DeviceGray alternate | Regression check: renders grey already and should be left alone |
| `images/colour-key-masked-image.pdf` | RGB image with a `/Mask [min max ...]` colour-key array | Greying the samples would change which pixels the key hides, so it has to stay in colour with a warning |
| `jpeg2000/jpx-palette-indexed.pdf` | JPX with a `pclr` palette box, drawn through the PDF's own `/Indexed` space | Greyscale decoded it as solid black instead of reading the indices against the PDF palette |
| `jpeg2000/jpx-two-component-devicen.pdf` | Raw two-component JPX codestream in a two-colorant `/DeviceN` space | PDFBox writes only one band of the decoded image, so reading it against DeviceN failed with an end-of-file error |
| `structure/pdfa-claim-without-output-intent.pdf` | Claims PDF/A-2B in its XMP, paints only in CalRGB, has no output intent | DeviceGray in PDF/A needs a `GTS_PDFA1` output intent; without adding one, greyscale broke PDF/A validity. Not itself checked with veraPDF: it is a structural sample, not a conformance reference. |
| `structure/article-beads-without-threads.pdf` | A page `/B` array of beads, but no `/Threads` in the catalog | The beads are unreachable and can be dropped |
| `structure/links-to-orphan-page.pdf` | A link, a GoTo action and the catalog `OpenAction` all point at a page object that is not in the page tree | The links keep an invisible page (and its resources) alive; they can be dropped |
| `structure/metadata-streams-on-page-and-image.pdf` | XMP streams on the catalog, a page and an image, with no PDF/A claim | Only the catalog's XMP needs to be kept byte for byte |
| `structure/signature-field-present.pdf` | A filled signature field (dummy `/ByteRange`) | Any rewrite invalidates a signature; tools should leave the file unchanged and say so |
| `encryption/owner-password-aes256.pdf` | AES-256 with an owner password only | Output differs on every run because of the random IV; decrypt before comparing bytes |

## Known gap

`pdf.js`'s test file `issue13147.pdf` (a Japanese CFF CID font that PDFBox reports as
damaged) came out of the optimizer as a blank page. A synthetic font with a fully
broken CFF program doesn't reproduce it; it needs a CFF that partly parses. That file
isn't included because its licence is unclear. A licence-clean, partly broken CFF
font would be a good addition.

## Checking two builds

[`../scripts/compare_optimizer_runs.sh`](../scripts/compare_optimizer_runs.sh) runs two
`office-convert` builds over a folder and reports changed failures, byte differences
and render differences (it needs `pdftoppm`):

```bash
common/scripts/compare_optimizer_runs.sh BASE_CLI NEW_CLI common/optimizer /tmp/out
common/scripts/compare_optimizer_runs.sh BASE_CLI NEW_CLI common/optimizer /tmp/out --grayscale
```
